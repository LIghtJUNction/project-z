# SSMCP 781 与 FC：原始证据独立配对核对

**结论：原件之间未发现实质不一致。七类样本的最终可见完成耗时均下降，但部分反馈和分段耗时变长，必须同时报告。** 这是一轮固定源码、相同方法的先后配对观察，每类每版只有一次记录，不提供统计置信或一般性能保证。

本次只读取已有 JSON/ZIP 并重新计算，不执行产品、构建、测试或 GUI，不重新散列 ELF，不改变源码或引用。

- 基线：`781b87df1d364137b6885f17f631a3e9e991bd58`，tree `6bf7beb143cfdce3878df856c27785164695430f`。
- 候选：`fc06728a36d0b4d2920e1e2bc29885721ced5780`，tree `088fe1cde36fe63a33df1f9b7cfb619ae5f8ee35`。其唯一父提交为上述基线，四路径差异由既有固定 GitHub 来源观察确认。
- 两轮 execution cohort 整对象相同；构建配置、Cargo.lock、依赖清单、gitlink、编译器与 profile 一致。构建环境仅各自 TMPDIR 路径不同。冻结 r3 驱动、Ctrl+V supplement、文件粘贴 helper、私有 clipboard reader 及完整 helper 集合哈希一致。
- 六个样本顺序、输入字节数/哈希、括号模式、预期接受/拒绝/inline 类型逐项相同；Ctrl+V 同为一个 `0x16` PTY 字节触发同一合成内容。80 与31条有序检查清单相同，Next caller 路由检查也保留。
- 候选回执引用的基线 execution、six-case、Ctrl+V 大小及 SHA256，分别精确匹配现有基线原件；不是较早失败轮次。

## 执行、忙碌输出与锁

候选两条运行命令均exit0。执行回执墙钟共193.300145s，其中等待quiet lock 169.038702s，拿锁到回执完成24.261430s；等待时间没有混入样本的单调时钟计时。锁在2026-11-21T00:02:29.965308+00:00释放，记录的device34/inode63537699与基线相同。本次未探测当前锁状态。
忙碌producer两轮均在输入前后保持运行并产生输出，记录tick为20→14。各自观察延伸到ready之后748.808433ms与1285.311678ms；首个后续输出在ready后0.584604ms与1.345593ms。计数窗口不同，不能把tick除以ready_ms解释成吞吐率，也不能仅凭20→14称输出退化。
80+31是夹具检查条目，含重复执行的逐样本断言，不是111个Rust单元测试。两轮输入快照、运行源码/fixture集合和产物在各自执行前后保持一致。
