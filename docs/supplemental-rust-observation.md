# Supplemental Rust architecture observation

The supplemental catalog is separate from the Project Z gitlink catalog. It records an inventory of 115 active public, non-fork repositories owned by LIghtJUNction outside Project Z; 81 have no Cargo manifests and are not Rust targets. The remaining 34 repositories contain 36 independent Cargo workspaces. URLs and refs are not accepted from Actions inputs; the observer constructs an anonymous GitHub URL with the verified owner and fetches only the reviewed catalog SHA.

Use the manual workflow with profile `smoke` (bilibilive, coolapk-cli, emailctl, markref), `native` (the two qualified native roots and pinned-context lightflow-rig), or a shard number `0`–`6` for the current inventory. The dedicated profiles `remaining-0` through `remaining-5` cover all current non-smoke candidates without rerunning the smoke set. Each numbered shard contains at most four candidate workspaces, sorted by repository and manifest. One hosted Linux runner processes a shard serially with the existing locked Cargo metadata and scanner timeouts, a 28-minute job cap, and two build/analyzer threads. No checkout credentials, no write token scopes, no secrets or release gate. The pilot uses analyzer/toolchain Rust 1.100.0: this measures its default Linux view, not a matrix across MSRV, feature sets and targets.

`report.json` records every workspace as `clean`, `findings`, `tool_error`, `environment_review` or `not_selected`. The nine `environment_review` entries are explicitly not executed pending validation of Android targets, native media/desktop dependencies or custom registries. `not_selected` is coverage remaining outside the selected shard, not a passed scan. Findings are advisory; tool errors are visible on the standalone workflow. The artifact retains report and per-target logs for seven days.

To enable a held workspace, verify toolchain requirements, Cargo resolution and representative analyzer coverage in a hosted run, then update its reviewed catalog entry. Refresh pinned SHAs explicitly and preserve the separation from the canonical Project Z index. No source changes or suppression files are generated.

## Validation and environment coverage

- [Four-workspace smoke](https://github.com/LIghtJUNction/project-z/actions/runs/45453184630): 3 clean, 1 findings, no tool errors.
- [Six bounded shards](https://github.com/LIghtJUNction/project-z/actions/runs/45454249052): 22 distinct initial follow-up workspaces, 4 clean and 16 with findings. The two LightFlow plug-ins failed at setup; artifact 14951030642 confirms the missing relative host manifest.
- [Native qualification](https://github.com/LIghtJUNction/project-z/actions/runs/45455460974): LightFlow and Magpie desktop completed default Linux inspection with 26 and 8 findings respectively. Optional accelerated features, UI builds and non-Linux targets were not exercised. LightFlow Rig was clean in a composed snapshot with an exact pinned public LightFlow host and unchanged tracked lock; the production observer now uses that pinned layout only for the reviewed Rig root.
- LightFlow Std resolves its relative path with the LightFlow v0.1.4 host but still needs a lockfile change under locked metadata, so it remains on explicit environment review rather than weakening reproducibility. Other holds include Android/NDK targets, missing native lockfiles, native/media features, custom registries and plug-ins requiring broader environment review.
